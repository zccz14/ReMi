# Interview: 对话式认知发现

## 定义

Interview 是通过多轮对话持续显化本体认知的应用场景。

它不是单纯的聊天，也不是纯粹的问卷，而是一种有明确目标的认知发现协议：系统通过提问、追问、去重和边界控制，逐步把隐含知识转化为可审批的锚点与探针。

## 适用场景

- 本体愿意直接表达想法、偏好、价值判断与经验解释
- 某个认知领域需要继续深挖，不能只靠已有材料被动提取
- 系统已经发现关键探针，需要通过对话补全答案
- 希望在采集过程中同时检验回答的稳定性与一致性

## 核心判断

访谈信息质量 = **控制感 x 价值感 x 相关感**。

任何一项接近零，整场访谈都会塌：

- 没有控制感，对方会防御或退出
- 没有价值感，对方会觉得只是被采样
- 没有相关感，问题再精致也只是噪音

## 最小协议

AI 主持人的最小可行协议分五层：

1. **目标层**：始终优化“问题对齐 + 隐含知识显化”
2. **策略层**：严格执行“先轻量 -> 再求新 -> 最后具体”的三步提问协议
3. **状态层**：识别受访者状态（愿意聊 / 防御 / 疲劳 / 跑题），切换提问模式
4. **去重层**：实时利用已有锚点、探针与对话上下文，避免重复追问
5. **审计层**：所有引用可追溯，所有追问有链路

## 提问原则

坏问题的优先级：**太重 > 太旧 > 太空**。

对应策略是：

- 先让对方说得出来
- 再证明这次对话值得
- 最后才用具体证据做深追问

冷启动时不装懂，先声明边界，给选择权，用时间锚点降低启动门槛。对方不想聊时，可以从开放题切到选择题。

## 与锚点/探针的关系

- 当系统已经知道某个问题值得问，但答案还不稳定时，产出的是**探针**
- 当某个问题获得了足够稳定、可审批的回答时，才形成**已回答锚点**
- 访谈过程中也会用到推理与召回：如果系统已经知道答案，就不应该重复追问；如果当前问题依赖已有关系背景或表达边界，也需要先召回再提问

## 成功标准

- 用户愿意继续对话，而不是被问退
- 重复问题明显减少
- 新产出的候选锚点具有审批价值，而不是流水账
- 探针能够逐步缩小，而不是无限堆积
