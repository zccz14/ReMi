# 灵魂锚点页时间信息与统计页移除设计

## 背景

当前灵魂锚点页已经支持搜索、编辑、新增和删除，但仍存在三个直接影响可用性的问题：

- 列表没有展示锚点的创建时间和更新时间，用户无法判断哪些内容是最近新增或最近修改的。
- 列表排序仍按 `createdAt` 倒序，不能把最近维护过的锚点置顶，不符合“持续打磨锚点”的使用场景。
- `数据统计` 页面与灵魂锚点页存在信息重叠，其中 `totalAnchors` 对用户最有价值，但被放在独立页面里，导致信息分散。

用户已经明确本轮目标：

1. 灵魂锚点页显示每条锚点的创建时间与更新时间。
2. 灵魂锚点按更新时间降序排列。
3. 灵魂锚点页显示锚点总量。
4. 彻底删除当前数据统计页面，而不是仅隐藏入口。

## 目标

- 在灵魂锚点页展示总锚点数。
- 在每个锚点卡片中展示 `创建时间` 和 `更新时间`。
- 让锚点列表按 `updatedAt` 倒序排列，前后端语义一致。
- 删除统计页代码、路由和“我”页入口，避免重复信息入口。

## 非目标

- 不新增新的统计维度，如消息数、最近活跃日、来源占比等。
- 不在本轮改动锚点数据结构或数据库 schema。
- 不加入复杂筛选、分组、分页交互重构。
- 不调整锚点编辑、新增、删除的交互方式。

## 现状

- 前端锚点数据结构已经包含 `createdAt` 和 `updatedAt`，定义位于 `packages/web/src/hooks/use-anchors.ts`。
- 后端锚点接口已经返回 `total`，但 hook 当前只消费 `items`，没有把总量暴露给页面。
- 后端锚点列表接口当前按 `createdAt` 倒序，位于 `packages/server/src/routes/anchors.ts`。
- 前端仍保留独立 `StatsPage` 页面，路由挂在 `packages/web/src/App.tsx`，入口位于 `packages/web/src/pages/MePage.tsx`。

## 设计方案

### 1. 数据来源收敛到锚点接口

本轮不复用 `StatsPage` 的统计接口，也不让锚点页依赖两套数据源。

灵魂锚点页所需信息全部来自现有锚点列表接口：

- `items`：用于渲染锚点卡片
- `total`：用于渲染总锚点数

这样可以保证锚点页只依赖一个接口完成列表与总量展示，避免“列表刷新了但总数来自另一接口还没刷新”的不一致问题。

前端 hook 需要从当前 `GET /anchors?limit=200` 响应中同时保存：

- `anchors`
- `total`

`create / update / remove` 成功后继续沿用当前的 `reload()` 流程，这样总量和排序都能通过一次重新拉取自然同步。

### 2. 后端排序改为按更新时间倒序

锚点页要求按更新时间降序展示，因此排序语义应由后端直接提供，而不是让前端在拿到数据后自行二次排序。

后端 `GET /:pubKey/anchors` 改为：

- 主排序：`updatedAt desc`
- 次排序：`createdAt desc`

加入次排序的目的，是在多个锚点 `updatedAt` 相同的情况下保持结果稳定，并让新建但尚未再次编辑的锚点仍有合理顺序。

这样做的好处是：

- 前端和后端语义一致，避免未来分页时前端排序失真。
- 新建锚点和刚编辑过的锚点都会自然浮到顶部。
- 以后如果锚点页增加分页，也不会因为本地排序导致跨页错位。

### 3. 灵魂锚点页顶部展示总量

在 `AnchorsPage` 顶部搜索框附近增加一个轻量摘要区，直接显示当前总锚点数。

信息保持克制，只展示一项：

- `总灵魂锚点：N`

不在这里继续承载消息数、最近活跃时间等原统计页信息。原因是本轮目标是把与锚点强相关的信息收拢到锚点页，而不是把统计页整体搬过来。

这里的总量语义保持为“当前账号下的锚点总数”，不随前端搜索关键字变化。也就是说：

- 搜索只影响当前可见列表项
- 顶部总量始终展示接口返回的全量 `total`

这样用户既能知道当前账号一共有多少锚点，也不会把“搜索结果数”误解成“总锚点数”。

视觉上建议采用当前页面已有组件风格中的轻量文本或小卡片，而不是重新引入一个“统计面板”。重点是让用户进入页面后立刻看到规模信息，但不压过列表主体。

### 4. 每条锚点显示创建时间和更新时间

每个锚点卡片在问题、来源、答案之外，新增时间信息区，展示：

- `创建于 ...`
- `更新于 ...`

两项都始终显示，即使二者相同也不折叠。这样可以避免用户误解“是否从未编辑过”或“是否刚创建”。

时间展示采用本地化日期时间格式，由前端在页面层格式化即可，不需要后端预渲染字符串。

推荐展示原则：

- 保持为次级信息，使用较弱的文本层级
- 优先保证移动端单列布局可读，不引入拥挤的多列排版
- 不在本轮引入相对时间文案（如“3 小时前”），避免额外刷新逻辑

新增时间标签与总量标签都必须接入现有 i18n 资源，而不是直接在组件里硬编码中文。当前项目通过 `packages/web/public/locales/zh/translation.json` 与 `packages/web/public/locales/en/translation.json` 提供文案，因此本轮至少需要为锚点页新增对应键位，例如：

- `anchors.total`
- `anchors.createdAt`
- `anchors.updatedAt`

格式化后的具体时间字符串仍可由浏览器本地化能力生成，但标签文本必须进入翻译资源。

### 5. 删除统计页及其入口

用户已经明确选择彻底删除统计页，因此本轮删除范围包括：

- `packages/web/src/pages/StatsPage.tsx`
- `packages/web/src/App.tsx` 中的 `/stats` 路由
- `packages/web/src/pages/MePage.tsx` 中的 `数据统计` 入口
- 与统计页仅相关的无用 import
- `packages/web/test/pages/StatsPage.test.tsx`
- `packages/web/test/pages/App.test.tsx` 中对 `StatsPage` 的 mock

如果实现过程中发现还有其他只服务于统计页的测试桩、翻译键或辅助逻辑，也应一并清理，目标是做到“无入口、无路由、无组件、无专属测试、无死引用”。

删除后，`我` 页菜单顺序自然收缩为：

- 灵魂锚点
- 分享
- 设置

本轮不做 `/stats -> /anchors` 重定向。原因是用户已明确要求删除页面，而且当前产品内入口也将同步删除，没有必要继续维持已废弃路径。

## 数据与流程影响

本次不修改数据库 schema，也不新增接口。影响分为两部分：

- 后端：锚点列表接口调整排序字段
- 前端：锚点 hook 暴露 `total`，锚点页承接总量与时间信息，统计页相关代码被删除

`/interview/status` 接口本轮不删除。它当前虽然被统计页消费，但也可能仍属于访谈流程状态接口的一部分；在没有用户明确要求清理后端统计接口的前提下，本轮仅移除前端统计页依赖，不扩大到后端接口裁剪。

对现有 CRUD 流程的影响如下：

- 新建锚点后，由于 `createdAt === updatedAt === now`，新锚点会出现在顶部
- 编辑锚点后，`updatedAt` 刷新，卡片会在 reload 后移动到更前面
- 删除锚点后，总量会随 reload 一并更新

## 错误处理与回退

- 如果锚点列表请求失败，沿用当前 hook 的错误提示逻辑，不新增独立错误视图。
- 如果没有任何锚点，总量显示为 `0`，页面继续展示空态文案。
- 如果时间字段存在但值异常，前端应尽量容错格式化，最差退回空字符串或占位，而不是让整个页面崩溃。

本轮不为时间格式化增加复杂降级策略；默认依赖浏览器原生 `Date` 与 `Intl` 能力即可。

## 验收标准

满足以下条件视为完成：

1. 灵魂锚点页顶部能看到总锚点数。
2. 每条锚点卡片都显示创建时间与更新时间，且展示粒度至少包含日期和时间，不退化为只有日期。
3. 锚点列表按 `updatedAt` 倒序展示。
4. 编辑某个旧锚点后，刷新结果中该锚点会提升到更靠前的位置。
5. `我` 页不再显示数据统计入口。
6. `/stats` 路由不再由前端应用注册。
7. 统计页组件文件已删除，不保留死代码。
8. 即使个别锚点时间值异常，页面也会局部降级展示而不是整体渲染失败。

## 测试与验证

### 前端页面验证

- 验证锚点页在有数据时能显示总量、时间信息和正常列表。
- 验证锚点页在空数据时总量显示 `0`，空态仍正常显示。
- 验证输入搜索词后，列表会过滤，但顶部总量仍显示账号全量总数而不是过滤结果数。
- 验证编辑某条锚点后，reload 结果顺序符合更新时间倒序。
- 验证“我”页菜单中已无统计页入口。

### 路由验证

- 验证应用路由定义中不再包含 `/stats`。

### 测试清理验证

- 验证与 `StatsPage` 直接对应的页面测试已删除或改写，不再引用被移除组件。
- 验证 `App` 路由测试中的页面 mock 已同步清理，不再 import 或 mock `StatsPage`。

### 后端接口验证

- 为锚点列表接口增加或更新测试，确认返回结果按 `updatedAt desc` 排序。
- 至少覆盖一个“旧锚点被更新后排到新锚点前面”的场景。

### Hook 与文案验证

- 验证 `useAnchors` 除 `items` 外也能正确暴露 `total`。
- 验证新增的锚点页文案键已进入中英文翻译资源，页面不出现缺失 key 的回退文本。

- 增加相对时间显示与精确时间 tooltip
