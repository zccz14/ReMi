# AI 分身先调查后推理 Prompt 设计

## 背景

当前 `packages/server/src/avatar/message-augmentation.ts` 中的 platform prompt 只要求分身以 owner 身份回复，并尊重高优先级指令，但没有明确要求它在依赖调用方环境时先做环境判断与补问。结果是分身可能在缺少上下文时，直接进入分析、建议或推理。

## 目标

- 让分身在需要依赖调用方环境时，先了解环境，再继续推进
- 保持自然对话感，避免把所有回答都变成机械盘问
- 只通过 prompt 行为约束完成这次改动，不引入新的协议层或额外运行时状态

## 非目标

- 不改动消息结构
- 不新增工具调用或函数调用协议
- 不要求分身在所有问题上都先追问

## 设计

### 1. 新增“决策前调查门槛”

在 platform segment 中加入一组短规则，明确说明：

- 如果回答会受到调用方环境影响，不能直接开始推理
- 调用方环境至少包括：当前任务/目标、约束边界、与分身的关系语境
- 关键环境信息缺失时，必须先补最小必要问题
- 只有在关键信息已澄清后，才能继续分析、给建议、做计划或下结论
- 如果必须在信息不完整时先回答，要明确写出假设，而不是把假设伪装成事实

为避免实现漂移，增加最小判定规则：

- 如果当前回复要输出建议、计划、执行步骤、判断结论、风险评估，而这些内容依赖目标、约束、权限、时间或关系边界中的缺失信息，则先补问
- 如果当前回复属于通用知识解释、定义说明、低风险改写、与环境无关的直接事实回答，则可直接回答
- 如果当前对话和已注入上下文已经足够支撑判断，则不重复追问

正反例：

- “帮我决定要不要现在重构这段服务” -> 应先问目标、约束、风险边界
- “帮我写一个正则匹配邮箱” -> 可直接回答
- “我该不该现在跟对方摊牌” -> 应先问关系语境与目标
- “解释一下什么是 SSE” -> 可直接回答

### 2. 保持“最小必要补问”而非泛化盘问

prompt 不要求分身每次都完整盘问三类信息，而是要求它先判断：这些信息是否会实质影响当前回答。只有在会影响结论时，才补问最关键缺口。

推荐的优先顺序：

1. 当前在做什么、目标是什么
2. 有哪些约束、权限、资源、时间或不能做什么
3. 调用方与分身的关系语境，以及这次沟通要达到什么目的

这里的“关系语境”收窄为只在会影响结果时才追问的最小集合：

- 你代表谁发言，或要对谁输出
- 你与对方的关系是否会影响语气、边界或行动建议
- 是否存在权限、责任或身份边界

如果这些关系因素不会影响当前回答，则不要额外追问。

补问策略要求：

- 优先补最影响当前判断的一项，不做全量问卷
- 默认一次问 1-3 个关键问题
- 已有上下文足够时不重复确认

如果用户明确要求立即给出判断，而关键信息仍不足，可以先给条件化回答，但必须显式写出假设，例如：

`在你还没说明部署权限和发布时间窗口的前提下，我先按“你能独立发版、且今晚可回滚”这个假设给一个临时建议。`

### 3. 保持当前消息装配边界

这次只修改 `buildPlatformSegment()` 生成的 system 文案，不改：

- caller system 的拼接方式
- avatar identity segment
- recall segment 的 role 与注入顺序

这样可以把行为变化收敛在 platform instruction，避免把本次优化扩大成消息协议改造。

## 测试策略

- 确定性测试：更新或新增针对 `buildPlatformSegment()` 的断言，确保新规则文本被稳定注入
- 样例基线：整理一组 canonical prompts，作为人工验证与测试注释基线，至少覆盖三类：
  - 应先补问：需要目标/约束/关系语境才能可靠决策的问题
  - 不应补问：通用知识、定义解释、低风险直接回答
  - 可先条件化回答：用户明确要求先给临时判断，但关键信息不足
- 如果做行为导向测试，不要求验证真实 LLM 自由生成结果，而是验证 prompt 中的行为规则和样例意图一致，避免引入不稳定的非确定性测试

## 风险与缓解

- 风险：prompt 变长后，语言可能更僵硬
  - 缓解：使用 4-6 条短规则，避免写成长篇 SOP
- 风险：模型过度追问
  - 缓解：明确写入“只问最小必要问题”
- 风险：低风险问题也被拦住
  - 缓解：明确只有在环境会实质影响回答时，才先调查
- 风险：忽略已有上下文，重复追问
  - 缓解：明确要求先使用现有 message 和已注入上下文，只在关键缺口仍存在时补问

## 与现有规则的兼容

- 分身仍然必须优先服从更高优先级的 system 指令与安全边界
- “先调查后推理”只在不与更高优先级规则冲突时生效
- owner 身份扮演不等于在信息不足时强行替调用方下判断，身份化表达仍需建立在足够上下文或显式假设之上

## 验收标准

- platform prompt 明确体现“依赖环境时先调查，后推理”
- prompt 明确覆盖任务上下文、约束边界、关系语境三类环境信息
- prompt 明确要求最小必要补问与显式假设
- 现有消息装配边界不被扩大修改
- 对通用知识和低风险直接回答场景，prompt 不鼓励默认追问三类环境信息
- prompt 明确要求优先利用已有上下文，避免重复提问
