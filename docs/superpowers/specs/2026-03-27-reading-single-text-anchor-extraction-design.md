# 阅读：单长文本灵魂锚点提取实验设计

## 执行摘要

- `阅读` 是与 `访谈` 并列的正式入口，但本轮只做单长文本实验，不做 URL 和多语料管理。
- 用户从 `发现` 页进入独立 `阅读` 页面，一次粘贴一份长文本。
- 系统先提取候选灵魂锚点，并把它们组织成一份逐条作答的阅读理解问卷。
- 每题只展示 `问题 + 答案`，用户必须在 `认可 / 问题不对 / 答案不对` 中三选一。
- 所有题目默认未作答，没有默认 `认可`。
- 点击选项只修改单题状态，不立即入库、不立即丢弃、不立即重生成。
- 用户必须完成本轮所有题目后，才能统一提交本轮。
- 提交时才统一分流：`认可` 入库，`问题不对` 丢弃，`答案不对` 进入下一轮答案重审。
- 每轮提交后，系统总结已覆盖主题，并给出 `3-5` 个可能遗漏的话题建议。
- 用户可以基于这些建议继续下一轮增量提取，也可以结束本次阅读。
- v1 必须定义最小 `reading session` 状态模型、每轮题量上限、输入长度边界和结束语义，避免不同实现分叉。
- 成功标准首先是“批改负担低、用户愿意继续用”，其次才是提取量和增量收益。

## 背景

当前 ReMi 已有 `访谈` 作为灵魂锚点采集入口，但用户已经明确提出另一条并列入口：`阅读`。

这条入口不是让 AI 继续通过多轮对话挖掘用户，而是让用户直接提供一段已经写好的长文本，由 AI 先读，再把理解结果组织成一份可批改的“阅读理解问卷”。

本轮范围已经被用户主动收紧，原因是当前目标不是一次性把整条能力线做全，而是先验证交互闭环是否成立。用户明确要求：

- `阅读` 先作为一个独立页面存在，并从 `发现` 页面进入。
- 这期只做 `读文本`，不做 URL 阅读。
- 用户一次只粘贴一份长文本，不做多语料管理。
- 不改灵魂锚点 schema，仍然是 `问题 + 答案`。

本次实验想验证四件事：

1. 针对一段长文本的灵魂锚点提取能力是否足够强。
2. 用户逐条批改这些候选锚点时，负担是否足够低。
3. 主题聚类作为辅助分组，是否能提升理解和批改效率。
4. 在同一段长文本上做多轮增量提取，是否还能持续挖出高价值新锚点。

## 目标

- 在 `发现` 页面增加 `阅读` 入口，并跳转到独立阅读页面。
- 让用户一次粘贴一份长文本，发起一轮“阅读提取灵魂锚点”实验。
- 系统从长文本中尽可能充分地提取候选灵魂锚点，并生成逐条可作答的问卷。
- 用户对每条候选锚点给出三选一反馈：`认可`、`问题不对`、`答案不对`。
- 一轮中所有题目都完成反馈后，用户统一提交；提交时才执行入库、丢弃和下一轮准备。
- 系统在每轮后给出已覆盖主题与可能遗漏主题，支持继续做下一轮增量提取。
- 当新增价值明显下降时，系统主动建议收束，但仍由用户决定是否结束。

## 非目标

- 不做 URL 抓取、正文抽取、网页降级策略。
- 不做多段材料、多语料集合、来源管理或材料标签。
- 不改灵魂锚点数据库 schema，不给锚点新增证据字段或来源位置字段。
- 不做复杂人工标注工作流，例如强制用户解释为什么“问题不对”。
- 不在本轮引入自动即时入库、即时重生成或边点边执行的副作用式交互。
- 不把 `阅读` 做成一份可视化分析报告；它首先是一个低摩擦问卷式批改流程。

## 产品定位

`阅读` 是与 `访谈` 并列的正式入口，但两者心智不同：

- `访谈`：AI 主动追问，从对话中挖锚点。
- `阅读`：AI 先读用户已有长文本，再把理解结果变成一份阅读理解问卷，由用户逐题作答。

这意味着系统默认不应把候选锚点当成“AI 已经确认的知识”，而应把它们视为“等待用户批改的理解题”。

产品成功的第一信号也不是“提取得多全”，而是“用户批改负担低，愿意持续使用这条入口”。

## 最小状态模型

为避免多轮增量提取、中途离开恢复和统一提交语义出现实现分叉，v1 需要显式定义一个最小 `reading session` 边界。

单个 `reading session` 至少包含：

- 原始长文本
- 当前轮候选题列表
- 每题当前单选状态：`未作答 / 认可 / 问题不对 / 答案不对`
- 每题可选纠偏提示
- 已提交轮次的摘要结果
- 当前轮之前已认可入库的锚点引用
- 当前轮总结中用户选择的遗漏主题与自由补充文本
- 候选池：尚未进入当前轮展示、但已被系统生成的候选题
- 重审队列：上一轮被标记为 `答案不对`、等待以“同一问题 + 新答案”重出的题

v1 的持久化承诺定义为：

- 刷新页面、前后台切换、返回后再进入时，当前 `reading session` 仍可恢复。
- 不要求跨设备同步恢复。
- 未完成 session 默认在最后一次活跃后保留 `24` 小时；超过后自动清理。
- 候选池与重审队列与 session 同生命周期持久化；session 清理时一并清理。
- 刷新恢复时，必须恢复到“当前轮题目 + 当前轮作答状态 + 候选池 + 重审队列”的粒度，不能仅恢复摘要后重新生成。
- 结束本次阅读后，该 session 视为 closed，不再自动继续生成新一轮。

这样可以把本轮能力清晰约束为“单设备上的可恢复会话”，避免把它误做成长期知识草稿系统。

## 入口与页面结构

### 1. 发现页入口

`发现` 页面新增一个 `阅读` 入口，视觉风格与 `Me` 页面中的菜单项保持一致：

- 整行可点击
- 左侧图标
- 中间标题与简短说明
- 保持现有产品的导航语言，而不是做成工具后台入口

这样做的目的是让 `阅读` 明确成为产品的一部分，而不是只存在于实验面板中。

### 2. 独立阅读页面

点击入口后进入独立页面，例如 `/read`（最终路径跟随现有路由命名风格）。页面按流程分为三个阶段，但同一时刻只突出一个主任务：

- 输入文本
- 批改问卷
- 本轮总结与下一轮决策

整体继续采用 mobile-first 单列布局；桌面端也以单主列为主，不做复杂双栏，以免稀释“连续作答”的节奏。

## 主流程

### 1. 输入阶段

页面初始状态提供：

- 一个大文本输入框
- 一句极短说明，例如“把一段长文本交给 AI，批量提炼灵魂锚点”
- 一个主按钮，例如 `开始阅读`

本轮不提供其他配置项。用户不需要选择粒度、模式、材料类型或提取策略。

v1 还需要明确输入边界：

- 过短文本：少于 `800` 字时做轻提示，但允许用户继续。
- 推荐输入区间：`800 - 50000` 字。
- 过长文本：超过 `50000` 字后直接阻止提交，不静默截断，而是提示用户压缩文本后重试。

v1 统一采用“字符数”作为边界单位，而不是 token。这样前后端校验、字数统计和错误文案都更稳定，也更适合中文长文本场景。

字符数口径统一定义为：

- 前后端都按 UTF-16 `length` 计数。
- 包含空格、换行和标点。
- 不做自动 trim。
- 不做 Unicode 归一化后再计数。
- 前端按同口径做预检，最终以后端校验结果为准。

统一文案约定：

- 少于 `800` 字：`这段文本有点短，可能提炼不出足够稳定的灵魂锚点，你也可以继续试试。`
- 超过 `50000` 字：`这段文本太长了。为保证阅读效果，请压缩到 50000 字以内再试。`

### 2. 首轮提取阶段

提交长文本后，系统对全文进行尽可能充分的候选锚点提取。这里的策略不是“只挑最保守的少量高置信锚点”，而是优先验证长文本的提取上限。

在 `50000` 字上限下，v1 需要明确“读全文”的工程契约：

- 产品语义仍然是“基于整段全文提取”，不能只基于摘要或截断后的前半段提取。
- 工程实现允许分块处理全文。
- 如果采用分块，必须在分块提取后做跨块去重、归并和主题整理，再进入每轮 `18` 题的组装流程。
- 禁止用“先把全文压成摘要，再只对摘要提取锚点”替代全文提取。

系统内部需要完成：

- 候选锚点提取
- 重复或高度相似候选的去重与归并
- 主题聚类

但用户界面不把“聚类”做成首要操作对象，而是仍然采用逐条问卷式批改。聚类只作为分组标题出现。

为了不让“尽可能充分提取”与“必须答完整轮”冲突，v1 必须定义每轮题量上限。v1 默认规则如下：

- 每轮最多展示 `18` 题。
- 单个主题组最多展示 `6` 题。
- 首轮按排序结果截取进入本轮的题目；超出上限的候选不丢弃，而是保留给后续轮次候选池。
- 如果高价值候选不足 `18` 题，则允许更少，不强行补满。

设计层在这里直接写死默认值，是为了保证实验结果可比，避免不同实现者在题量控制上自由发挥。

### 3. 问卷批改阶段

每条候选锚点都表现为一道问卷题，默认只展示：

- `问题`
- `答案`

并提供一个次级展开入口查看相关原文片段。默认不展示 AI 的提炼理由，以降低噪音和说服感。

每题只有三种可选反馈：

- `认可`
- `问题不对`
- `答案不对`

这三个按钮本质上都是单选状态，不是即时执行命令。

### 4. 本轮统一提交

用户必须完成本轮所有题目的反馈后，才能提交本轮。

提交前：

- 所有题目默认都是 `未作答`
- 没有默认选中的答案
- 用户可以反复修改每题状态
- 不发生任何入库、丢弃、重生成等副作用

提交时：

- 被标记为 `认可` 的候选，统一入库
- 被标记为 `问题不对` 的候选，统一丢弃，并作为下一轮的问题生成负反馈
- 被标记为 `答案不对` 的候选，保留问题并进入下一轮答案重审队列

统一提交比边点边执行更合适，因为这更符合“填写阅读理解问卷”的心智，也避免误触造成无二次确认的不可逆修改。

### 5. 本轮总结与下一轮

系统在本轮提交后，先生成一个轻量总结视图，而不是直接抛出下一轮候选。总结视图包含：

- 已覆盖主题的简短总结
- `3-5` 个可能遗漏的话题建议
- 一个自由文本输入，允许用户补充希望下一轮重点关注的话题

用户可以：

- 选择继续下一轮增量提取
- 选择已经足够，结束本次阅读

当系统判断新增价值明显下降时，应主动提示可以收束，但不强制结束。

这里还需要明确定义结束语义：

- 如果用户选择 `已经足够`，本次 session 立即 closed。
- 已提交轮次产生的结果保留。
- 尚未开始展示的下一轮候选与待重审队列不再自动继续。
- v1 不提供“结束后恢复并续跑同一 session”的能力。

## 交互模型

### 1. 问卷而不是即时审核器

`阅读` 的核心交互不是“审核候选锚点并立刻生效”，而是“回答一份由 AI 根据长文本生成的阅读理解问卷”。

这个模型带来四个直接后果：

- 每题必须有明确的 `未作答` 状态。
- 提交前不能预设默认答案，尤其不能默认 `认可`。
- 所有题目都作答完毕后才允许提交。
- 轮次提交是明确的边界，提交前后系统行为不同。

### 2. 逐条作答，主题分组辅助

用户直接逐条处理锚点，而不是先理解聚类结构。主题聚类只作为轻量分组标题，帮助用户在相近语境里连续作答。

这符合本轮实验目标：

- 真实测量逐条批改的负担
- 同时观察主题分组是否能辅助连续判断
- 避免“先理解簇再批改”的额外认知成本污染实验结论

如果聚类质量不足，主流程必须允许平坦列表或弱分组降级，不能因为主题聚类失败而阻塞整轮问卷提交。

### 3. `答案不对` 的可选纠偏

当用户把某题标记为 `答案不对` 时，可选填写一句纠偏提示。该提示只在本轮提交后才参与下一轮准备，不在点击当下立即触发新答案生成。

这样保留了轻量主流程：

- 大多数情况下，用户只需选状态
- AI 在下一轮统一重审这些答案
- 只有用户觉得 AI 老是偏时，才补一句高价值纠偏信息

下一轮题目组成规则在 v1 需要写清：

- 被标记为 `答案不对` 的题，下一轮优先以“同一问题 + 新答案”的重审项出现。
- 新提取题随后补充，而不是让重审题淹没在新题里。
- 如果重审项与新提取项语义重复，优先保留重审项。
- 重审项应在界面上带轻量标识，帮助用户理解“这是同一题的新版答案”。
- 如果重审项本身超过每轮 `18` 题 hard cap，则按上一轮出现顺序截取前 `18` 题进入本轮，其余顺延到后续轮次。
- 如果某一主题下的重审项超过每组 `6` 题上限，则保留该主题按上一轮出现顺序的前 `6` 题，其余顺延到后续轮次；重审项不突破分组上限。

### 4. `问题不对` 的极简处理

用户已经明确要求：`问题不对` 不需要解释原因。原因是这类题一旦问题本身就错了，继续修补没有意义，也不应给用户增加额外负担。

因此 `问题不对` 的默认处理是：

- 本轮中仅记录单选状态
- 提交后统一丢弃
- 作为系统下一轮收紧问题生成策略的负反馈

## 界面要求

### 1. 输入区

- 单个长文本输入框
- 一个主动作按钮
- 不放复杂参数设置

如果文本明显过短，可做轻提示，但不应出现高压式校验文案。

### 2. 问卷列表

每个主题组由分组标题开头，下面是逐条题目。每题至少包含：

- 问题
- 答案
- `认可`
- `问题不对`
- `答案不对`
- `查看原文`

被标记为 `答案不对` 的题目，可局部展开一个轻量输入区，允许补充纠偏提示。

`查看原文` 的 v1 降级规则需要收敛为：

- 默认展示单个相关片段。
- 找不到稳定片段时，仅隐藏或降级该展开区域。
- 无论能否展示片段，都不影响该题作答与整轮提交。

### 3. 轮次提交区

页面底部需要始终有一个清晰的提交区，至少显示：

- 已作答数量 / 总题数
- 提交按钮

当存在未作答题目时：

- 提交按钮禁用
- 页面应明确提示“完成所有反馈后才能提交本轮”

当全部作答完成后：

- 提交按钮启用
- 用户点击后进入本轮统一处理

### 4. 本轮总结区

本轮提交后切换为总结视图，依次展示：

- 已覆盖主题
- 可能遗漏的话题建议
- 自由补充输入
- `继续挖掘`
- `已经足够`

这里的重点不是做大而全的分析报告，而是帮助用户低成本判断“是否还有值得继续挖的部分”。

## 系统行为

### 1. 首轮提取策略

首轮以“尽可能充分提取”为导向，但在展示前必须完成基础整理，避免把明显重复或轻微改写的候选一股脑抛给用户。

系统至少需要做：

- 去重
- 近似归并
- 主题分组
- 排序

排序建议优先考虑组内连贯性和题目可读性，而不是单纯按提取顺序输出。

### 2. 多轮增量提取策略

下一轮提取必须显式利用上一轮的反馈，而不是再次从零生成一批相似题目。系统需要吸收三类信号：

- `认可`：这些已入库锚点应被视为已覆盖，不再重复出题。
- `问题不对`：这些题型说明当前问题生成方式有偏差，下一轮应减少类似错误提问。
- `答案不对`：这些问题本身值得保留，但答案需要基于原文重审。

同时，系统还要结合用户对“遗漏主题”的选择或补充文本，把注意力导向尚未充分覆盖的部分。

“已覆盖主题 / 可能遗漏主题”建议的生成依据也需要收紧：

- 只基于原始长文本与本轮已提交反馈生成。
- 遗漏主题应显式排除已经被高置信覆盖的主题。
- 这部分输出以帮助下一轮提取为目标，不展开成长篇分析报告。

v1 下一轮组装算法需要固定为确定规则，避免不同实现分叉：

1. 先移除与已认可锚点高相似的题目，避免重复出题。
2. 再移除当前轮内语义重复项，重审题优先保留，新题丢弃。
3. 先放入重审队列中的题，按“上一轮出现顺序”排序。
4. 再放入基于遗漏主题与候选池产生的新题，按系统分数从高到低排序。
5. 组装时同时应用两层 cap：全轮最多 `18` 题、单主题最多 `6` 题。
6. 当 cap 冲突时，按上述顺序依次取题；一旦某主题已满 `6` 题，该主题剩余题顺延到后续轮次；一旦全轮达到 `18` 题，其余题统一顺延。
7. 因 cap 被顺延的题继续保留在候选池或重审队列中，直到被展示、被去重淘汰、session 结束或 session 过期。

这套规则的关键点是：重审题优先，但不突破总 cap 或主题 cap；候选池新题只在重审题之后补位。

### 3. 收束策略

系统应持续估计新增价值，例如：

- 新题中高价值成立项的比例是否持续下降
- 重复度是否上升
- 新题是否主要落在已覆盖主题的边缘变体上

当价值明显下降时，应主动建议收束，但保留继续一轮的入口，方便实验观察边际收益。

## 错误处理

- 如果长文本中可稳定提取的候选很少，直接说明“这段文本可稳定提炼的锚点较少”，并建议更换表达密度更高的文本。
- 如果某题无法稳定定位相关原文片段，不影响主流程批改；只在展开原文时做局部降级提示。
- 如果用户大量选择 `问题不对`，系统下一轮应自动收紧问题生成策略，而不是打断用户追问原因。
- 如果用户大量选择 `答案不对`，系统下一轮应优先修正答案质量，而不是继续盲目扩张题量。
- 如果用户中途离开页面，至少应保留本轮已选择的问卷状态，避免重新填写整轮问卷带来的挫败感。

## 验收标准

满足以下条件视为本轮设计落地成功：

1. `发现` 页面存在 `阅读` 入口，且样式语言与 `Me` 页菜单项一致。
2. 点击入口后能进入独立阅读页面。
3. 页面初始状态只要求用户输入一份长文本，不出现多语料管理 UI。
4. 系统能基于长文本生成按主题分组的逐条候选锚点问卷。
5. 每题默认没有预选状态，且必须在 `认可 / 问题不对 / 答案不对` 中三选一。
6. 在存在未作答题目时，用户不能提交本轮。
7. 点击题目按钮时不会立刻入库、丢弃或触发答案重生成。
8. 只有在提交本轮后，`认可` 项才统一入库。
9. `问题不对` 项在提交后被统一丢弃，并参与下一轮提取约束。
10. `答案不对` 项在提交后进入下一轮答案重审流程，且可携带可选纠偏提示。
11. 每轮提交后，系统会展示已覆盖主题与 `3-5` 个可能遗漏的话题建议，并允许自由补充关注方向。
12. 用户可在任意轮结束流程；当新增价值下降时，系统会主动建议收束。
13. `reading session` 在刷新或返回后可恢复当前轮状态，但不要求跨设备恢复。
14. 每轮题量存在明确上限，且超出部分不会一次性压到同一轮问卷中。
15. 下一轮中，`答案不对` 的重审题优先于新增题出现，且重复语义不会重复出题。
16. 结束本次阅读后，不再自动继续未开启的下一轮候选或待重审队列。
17. 输入长度存在明确上下界与统一降级文案，不会因实现差异产生不一致行为。

## 测试与验证

### 页面与路由验证

- 验证 `发现` 页新增的 `阅读` 入口可见、可点击。
- 验证入口文案与样式符合现有菜单项视觉语言。
- 验证阅读页面路由可正常访问。

### 输入与问卷状态验证

- 验证输入一份长文本后能生成候选锚点问卷。
- 验证超短与超长输入会触发统一的边界提示。
- 验证所有题目初始状态均为未作答。
- 验证单题只能三选一，切换时会覆盖原选择。
- 验证存在未作答题目时提交按钮保持禁用。
- 验证全部作答后才能提交。
- 验证每轮题量不会超过既定 hard cap。

### 提交流程验证

- 验证在未提交前，任何题目状态切换都不会触发入库或下一轮计算。
- 验证提交后，`认可 / 问题不对 / 答案不对` 三类结果会被一次性分流处理。
- 验证 `答案不对` 的纠偏提示会随本轮提交进入下一轮准备。

### 增量提取验证

- 验证第二轮不会简单重复首轮已认可题目。
- 验证第二轮会吸收上一轮的 `问题不对` 与 `答案不对` 反馈。
- 验证 `答案不对` 的重审题会优先出现，并保留与上一轮问题的关联。
- 验证用户选择或补充的遗漏主题会影响下一轮提取重点。

### 会话与结束语义验证

- 验证刷新页面后可恢复当前 `reading session` 的长文本、问卷状态和纠偏提示。
- 验证选择 `已经足够` 后，session 进入 closed 状态，不再自动生成后续轮次。

## 备选方案与放弃原因

### 方案 A：逐条问卷主流程 + 主题分组辅助（采用）

- 用户直接逐条回答候选锚点。
- 主题聚类只作为分组标题和上下文辅助。
- 优点是负担最轻，最符合本轮实验目标。

### 方案 B：先选主题，再进主题内批改（放弃）

- 用户先看主题簇，再决定进入哪个簇处理。
- 放弃原因是这会显著增加前置理解成本，污染“低批改负担”的实验结果。

### 方案 C：每轮只给极少高置信题（放弃）

- 每轮只展示很少的高置信题目，再逐步扩张。
- 放弃原因是吞吐偏低，不利于验证单长文本的提取上限和多轮增量价值。

## 里程碑

- Milestone 1：`发现` 页入口 + 独立阅读页面骨架 + 单长文本输入
- Milestone 2：首轮候选锚点问卷 + 三态单选 + 必答后提交
- Milestone 3：统一提交分流 + 已覆盖主题/遗漏主题总结
- Milestone 4：下一轮重审题优先 + 新题补充 + session 恢复
- Milestone 5：实验埋点与边际价值观察

每个里程碑都应能独立验证，不要求一次性把所有能力同时上线。

## 上线与回退

- v1 建议通过实验开关灰度放出，只在 `发现` 页暴露入口。
- 若实验效果不佳，最小回退方案是隐藏 `发现` 页入口并关闭相关路由入口。
- 回退不影响既有 `访谈` 流程和已有锚点库，因为本设计不改锚点 schema。

## 可观测性

为支持实验验证与线上排障，至少需要记录：

- 进入 `阅读` 页面次数
- 发起首轮阅读次数
- 每轮题目数、提交完成率、平均作答耗时
- 三类反馈的分布
- 下一轮继续率、结束率
- 每轮新增成立锚点数与边际下降趋势
- 原文片段展开率与失败率

这些埋点既用于评估“批改负担低不低”，也用于判断题量上限、聚类辅助和增量提取策略是否需要收缩。

最小排障与告警入口也需要明确：

- 生成失败：记录 session id、输入字数、失败阶段（首轮提取/下一轮提取/重审答案）、模型错误摘要。
- 恢复失败：记录 session id、恢复阶段、丢失字段列表。
- 提交分流失败：记录 session id、轮次、三类题目数量、失败分支。
- 下一轮构成异常：当重审题为空但存在 `答案不对` 提交、或总题数超出 hard cap 时，记录结构化错误日志。

v1 告警可先收敛为服务端错误告警，至少覆盖：

- 首轮/下一轮生成失败率在 `15` 分钟窗口内超过 `5%`
- 提交分流出现任意一次失败即告警
- session 恢复失败率在 `15` 分钟窗口内超过 `3%`

不要求本轮建设复杂监控面板，但必须让工程能够从日志和告警快速定位是哪一轮、哪一类环节出了问题。

### 实验效果指标

- 记录每轮题目总数、已认可数、`问题不对` 数、`答案不对` 数。
- 记录单题平均作答时间、整轮提交完成率、是否继续下一轮。
- 记录第二轮及后续轮次的新增成立锚点数量与边际衰减趋势。
- 观察主题分组是否提升连续批改效率，而不是增加额外理解负担。
