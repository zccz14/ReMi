# 头像裁剪约束修订设计

## 背景

当前头像裁剪流程已经切到 `react-easy-crop`，但交互约束仍然和产品意图不完全一致。

用户补充并确认了更严格的约束：

- 任意交互时刻，裁剪框都不能超出原图范围
- 裁剪框始终为正方形
- 初始状态取最大合法框，并按原图居中
- `Slider` 的最小值和最大值都必须受原图尺寸约束
- 原图短边小于最小要求时，图片不可上传，并展示友好的错误信息

## 最终确认的产品规则

### 尺寸门槛

- 头像原图的短边必须大于等于 `100`
- `100` 必须提取为单独常量，供校验、滑杆范围和测试复用
- 如果原图短边 `< 100`，则该图片不可用于头像裁剪与上传

### 错误反馈

- 对于短边 `< 100` 的图片，界面必须给出明确、友好的错误提示
- 推荐文案语义：`图片尺寸过小，头像至少需要 100 x 100 像素`
- 错误状态下确认按钮必须不可用

### 裁剪框规则

- 裁剪框始终为正方形
- 在原图坐标系中，裁剪框任意时刻都必须满足：
  - `0 <= x`
  - `0 <= y`
  - `x + size <= imageWidth`
  - `y + size <= imageHeight`
- 也就是说，裁剪框在任意时刻都完全落在原图内

### 初始状态

- 图片通过最小尺寸校验后，初始化裁剪框
- `maxSize = min(imageWidth, imageHeight)`
- `initialSize = maxSize`
- `initialX = (imageWidth - initialSize) / 2`
- `initialY = (imageHeight - initialSize) / 2`
- 这表示初始值为“原图最大内接正方形，且居中”

### Slider 规则

- `Slider` 控制裁剪框边长 `size`
- `minSize = AVATAR_MIN_CROP_SIZE`，即 `100`
- `maxSize = min(imageWidth, imageHeight)`
- 默认值为 `maxSize`
- 缩放时优先保持当前裁剪框中心
- 若缩放后即将越界，则对 `x / y` 做最小纠偏，而不是跳回图片中心

## 实现策略

### 状态真值

将头像裁剪状态统一为原图坐标系中的显式正方形：

- `x`
- `y`
- `size`

显示层、拖动、滑杆、导出都围绕这组状态工作，不再把库的视觉状态当成最终真值。

### `react-easy-crop` 的角色

- 保留其手势交互和可视裁剪 UI
- 但产品约束由我们自己的 source-space 收敛逻辑统一保证
- 在接收库输出时，对结果做正方形化与边界钳制

### 常量

新增统一常量，例如：

- `AVATAR_MIN_CROP_SIZE = 100`

该常量应被以下位置复用：

- 图片尺寸准入校验
- `Slider` 最小值
- 错误提示文案插值或测试断言
- 相关测试用例

## 文件改动

### `packages/web/src/components/profile/AvatarCropDialog.tsx`

- 提取最小头像尺寸常量
- 在图片加载完成后检查原图短边是否小于最小值
- 若小于最小值：
  - 设置友好错误提示
  - 清空可导出裁剪状态
  - 禁用确认按钮
- 若通过校验：
  - 以“最大合法框居中”初始化裁剪状态
  - 将 `Slider` 范围限制在 `[100, 原图短边]`
  - 在拖动和缩放后，对导出裁剪区域做 source-space 正方形钳制

- 增加 `Slider` 最小值为 `100`、最大值为原图短边的测试
- 增加交互过程中导出的 `croppedAreaPixels` 不超过原图短边的测试

## 验收标准

- 原图短边 `< 100` 时，用户无法确认上传，且能看到明确错误提示
- 通过校验的图片在初始状态下使用“最大合法正方形居中”裁剪框
- `Slider` 范围始终为 `[100, 原图短边]`
- 任意交互时刻，裁剪框都不会超出原图范围
- 导出的正方形区域边长始终不超过原图短边
- `100` 以单独常量存在，不允许在实现与测试中散落硬编码

## 细化约束

### 边界值

- `100 x 100`、`100 x N`、`N x 100` 必须被接受
- 当原图短边恰好等于 `100` 时：
  - 无错误提示
  - 确认按钮可进入可用状态
  - `Slider` 的最小值与最大值都为 `100`
  - 初始裁剪框边长为 `100`

### 唯一真值收敛

必须存在唯一的 canonical 裁剪收敛逻辑，初始化、拖动、滑杆变化和导出全部复用这套逻辑。

输入为库输出或候选状态，输出为 canonical `x / y / size`。

收敛顺序必须明确为：

1. 先将候选裁剪区域收敛为正方形，规则为 `size = min(candidateWidth, candidateHeight)`
2. 以候选区域中心为中心生成正方形 `(x, y, size)`
3. 再执行边界钳制：
   - `x = clamp(x, 0, imageWidth - size)`
   - `y = clamp(y, 0, imageHeight - size)`
4. 导出只能来自这份 canonical `x / y / size`
5. 导出时仅对最终像素值做一次取整
6. 不允许直接信任未经收敛的库回调值用于导出

### 中心保持与最小纠偏

- 缩放后如果新正方形仍完全合法，则裁剪框中心保持不变
- 缩放后如果将越界，则仅移动达到合法所需的最小 `x / y` 距离
- 不允许因缩放而无故跳回整图中心

### 错误态恢复

- 一张不合法图片触发错误后，重新加载合法图片或重新打开对话框时，错误必须被清除
- 恢复后应重新进入“最大合法框居中”的初始状态
- 恢复后确认按钮应按正常就绪逻辑重新启用

## 补充测试要求

- 覆盖 `100x100`、`100xN`、`Nx100` 的合法边界值
- 覆盖拖动到四边与四角后的完整不变量：
  - `x >= 0`
  - `y >= 0`
  - `x + size <= imageWidth`
  - `y + size <= imageHeight`
- 覆盖缩小、放大到最大值后的完整不变量
- 覆盖“缩放时中心保持；越界时最小纠偏”的行为
- 覆盖无效图片报错后切换到合法图片的恢复路径

### `react-easy-crop` 适配层

- canonical `x / y / size` 是唯一真值
- 库的 `crop / zoom / croppedAreaPixels` 只作为输入或显示适配结果，不作为最终导出真值
- 从库回调进入业务层时：
  - 将 `croppedAreaPixels` 视为候选区域输入
  - 先走 canonical 收敛逻辑，再更新业务状态
- 从业务状态驱动 UI 时：
  - 由 canonical `x / y / size` 反推出库所需显示状态
  - 如果显示状态与库内部状态有偏差，以 canonical 状态为准
- 导出时只能读取 canonical `x / y / size`

### 像素取整规则

导出前的最终像素收敛规则固定为：

- `size = floor(size)`
- `x = clamp(round(x), 0, imageWidth - size)`
- `y = clamp(round(y), 0, imageHeight - size)`
- 取整后必须再次保证：
  - `x + size <= imageWidth`
  - `y + size <= imageHeight`

测试断言必须复用同一规则，不允许各处自行定义不同的 rounding 语义。
