# PWA 安装引导按钮设计

## 背景

ReMi Web 已完成 PWA installability 基础改造，应用现在可以被浏览器识别并安装。但当前仍缺少一个稳定、明确的安装入口，用户只能依赖浏览器地址栏图标、系统提示或自行摸索安装路径，安装转化完全依赖平台默认行为。

本次任务是在不扩大范围的前提下，为 Web 端增加一个用户可感知的安装入口，让未以 PWA 运行的用户可以在应用内主动发起安装，同时在不支持原生安装提示的环境中仍能获得清晰的手动安装指导。

## 目标

- 在 `【我】` 页面增加一个显式的 `安装 PWA 应用` 按钮。
- 仅在当前运行环境不是 PWA 时显示该按钮。
- 点击按钮时优先触发原生安装流程，失败或不可用时回退到平台化手动安装说明。
- 手动安装说明至少区分 `iPhone/iPad`、`Android`、`桌面浏览器` 三类环境。

## 非目标

- 不在首页、设置页、首次进入横幅等其他位置增加安装入口。
- 不在本轮加入安装埋点、安装转化分析或实验开关。
- 不新增截图教程、视频教程或专门安装帮助页。
- 不调整 service worker、缓存策略或离线业务能力。

## 现状

- 当前项目已经具备可安装的 manifest、图标和截图资源。
- 当前应用内没有显式安装 CTA。
- 不同平台的安装入口差异较大：
  - Chromium 类浏览器通常可以通过 `beforeinstallprompt` 触发原生安装。
  - iOS Safari 没有统一可编程安装事件，通常只能通过“添加到主屏幕”手动完成安装。
  - 桌面浏览器对安装 UI 的呈现也存在地址栏图标与浏览器菜单差异。

## 设计方案

### 1. 入口位置与显示规则

在 `【我】` 页面增加一个 `安装 PWA 应用` 按钮。

显示规则保持克制：

- 当检测到当前已经以 PWA 运行时，不显示该按钮。
- 当检测到当前仍在普通浏览器环境中运行时，显示该按钮。

这里的“PWA 运行态”采用运行方式检测，而不是依赖 UA 推断。推荐组合判断：

- `window.matchMedia('(display-mode: standalone)').matches`
- `window.navigator.standalone === true`（作为 iOS 补充）
- 必要时补充 `document.referrer.includes('android-app://')` 兼容特殊 Android 宿主

最终对页面暴露统一布尔值 `isPwaMode`，页面本身不直接处理平台兼容分支。

### 2. 点击行为：优先原生安装，失败回退说明

按钮点击后采用单入口智能分流：

1. 如果当前存在可用的 `beforeinstallprompt` 事件，则优先触发原生安装。
2. 如果没有可用事件，或事件触发失败、失效，则打开平台化手动安装说明弹窗。
3. 如果用户在原生安装面板中取消安装，不视为错误，也不弹出额外失败提示，后续仍允许再次点击按钮。

这样可以同时覆盖：

- 支持标准安装提示的 Chromium 环境
- 不支持标准安装事件但仍可手动安装的 iOS Safari
- 安装入口分散在浏览器菜单中的桌面环境

### 3. 状态来源与组件结构

新增一个轻量的 PWA 安装能力封装，统一管理三类状态：

- `isPwaMode`：当前是否以 PWA 运行
- `installPromptEvent`：是否已捕获可复用的安装提示事件
- `platform`：当前平台类型

建议职责拆分如下：

- 一个 PWA 安装状态模块或 hook，用于：
  - 在应用根层尽早监听 `beforeinstallprompt`
  - 缓存可复用事件
  - 监听 `appinstalled`
  - 计算 `isPwaMode`
  - 识别平台类型
- `【我】` 页面仅消费该状态与动作：
  - `isPwaMode === true` 时隐藏按钮
  - `isPwaMode === false` 时显示按钮
  - 点击时调用统一动作 `installOrShowGuide()`
- 一个独立的安装说明弹窗组件，用于按平台展示引导内容

这样做可以保证页面层足够薄，未来如果要把相同入口复用到设置页或首页，也不需要复制浏览器兼容逻辑。

这里必须明确：`beforeinstallprompt` 的监听不能等到 `【我】` 页面挂载后再注册，否则用户先进入其他页面时可能已经错过事件。正确做法是在应用启动后的根层或全局状态层注册监听，并让页面只消费已经缓存的状态。

### 4. 平台化手动安装说明

当无法直接触发原生安装时，弹出安装说明弹窗，并按平台展示最小可用步骤。

#### iPhone / iPad

- 提示必须使用 Safari 打开当前页面
- 提示点击分享菜单
- 提示选择“添加到主屏幕”

#### Android

- 提示打开浏览器菜单
- 提示选择“安装应用”或“添加到主屏幕”

#### 桌面浏览器

- 提示查看地址栏中的安装图标
- 或从浏览器菜单中选择 `Install app` / `安装应用`

如果平台无法可靠识别，则回退到一套简短的通用说明，避免出现“按钮可点但没有后续指引”的死路。

对于“不支持安装或宿主能力不明确”的环境，最小策略如下：

- 如果检测到常规浏览器环境但没有原生安装事件，仍显示按钮，并提供对应平台说明
- 如果检测到疑似 in-app webview、内嵌浏览器或无法完成安装的受限宿主，则仍可显示按钮，但说明内容优先提示“请用 Safari 或 Chrome 打开当前页面后再安装”
- 不要求在本轮精确枚举所有第三方宿主；实现只需保证未知环境不会给出误导性的唯一指令，而是落到通用说明与“改用 Safari/Chrome 打开”兜底

平台识别允许存在“不确定”状态，不把不确定环境强行归类到某个平台说明中。

### 4.1 平台识别边界

平台识别至少输出以下四类之一：

- `ios`
- `android`
- `desktop`
- `unknown`

识别来源可以组合使用 UA、平台信息与触控特征，但本轮不要求做到浏览器级精准识别。验收重点是：

- 常规 iPhone 能落到 `ios`
- 常规 Android 浏览器能落到 `android`
- 常规桌面浏览器能落到 `desktop`
- 无法稳定判断的平台落到 `unknown`

iPadOS 允许采用保守策略：若不能稳定识别为 `ios`，则降级到 `unknown` 并展示通用说明，而不是强行归入桌面浏览器说明。

### 5. 文案与国际化

按钮文案固定为：`安装 PWA 应用`。

安装说明弹窗中的标题、步骤、关闭按钮与兜底提示都应进入现有国际化资源，而不是写死在组件中。这样后续可以自然扩展英文文案，且不会把平台说明散落在页面实现里。

通用兜底文案应包含类似提示：若当前浏览器中未看到安装相关选项，请改用 Safari 或 Chrome 打开当前页面后再试。

## 数据与流程影响

本次不影响业务数据结构，不改动后端接口，也不修改 service worker 运行逻辑。影响集中在前端交互层：

- `【我】` 页面新增一个条件渲染的安装入口
- 应用启动时增加对安装事件与安装状态的监听
- 非原生安装环境可获得平台化手动安装引导

## 错误处理与回退

- 如果 `beforeinstallprompt` 从未触发，按钮仍显示，但点击后直接进入平台说明弹窗。
- 如果安装事件已失效或调用时报错，自动回退到平台说明弹窗，不向用户暴露技术性错误。
- 如果用户取消安装，保持当前状态，不弹错误提示，不自动隐藏按钮。
- 如果 `appinstalled` 触发，清空缓存事件并更新状态；当前会话中应关闭安装说明弹窗，并让页面进入“按钮不再显示”或在下一次渲染中不再显示的状态。
- 如果平台检测不确定，使用通用说明兜底。

`installPromptEvent` 视为一次性可消费资源：

- 调用 `prompt()` 后，无论用户接受还是取消，都不再假定该事件可重复使用
- 后续若浏览器再次派发新的安装事件，再覆盖缓存
- 如果当前没有新的事件，则继续走手动安装说明回退路径

## 验收标准

满足以下条件视为完成：

1. `【我】` 页面在非 PWA 环境下显示 `安装 PWA 应用` 按钮。
2. 当前应用已经以 PWA 运行时，`【我】` 页面不显示该按钮。
3. 当存在可用 `beforeinstallprompt` 事件时，点击按钮会优先触发原生安装流程。
4. 当不存在可用安装事件时，点击按钮会打开安装说明弹窗。
5. 安装说明弹窗至少能区分 `iPhone/iPad`、`Android`、`桌面浏览器` 三类说明。
6. 如果原生安装触发失败或事件失效，交互会自动回退到说明弹窗。
7. 无法稳定识别的平台会回退到通用说明，而不是错误归类到桌面或移动专属说明。
8. 所有新增用户可见文案进入国际化资源。

## 测试与验证

### 状态逻辑测试

- 验证 PWA 运行态检测逻辑在 `standalone`、`navigator.standalone` 等场景下行为正确
- 验证平台识别逻辑至少能区分 `iOS`、`Android`、`desktop`，并在无法稳定识别时返回 `unknown`
- 验证 `beforeinstallprompt` 捕获、缓存与清理流程
- 验证 `beforeinstallprompt` 监听注册在应用根层时，页面晚于事件发生挂载仍能消费缓存状态

### 页面渲染测试

- 验证 `【我】` 页面在非 PWA 环境显示按钮
- 验证 `【我】` 页面在 PWA 环境隐藏按钮

### 交互测试

- 验证存在安装事件时调用原生安装
- 验证不存在安装事件时打开平台说明弹窗
- 验证安装事件失效或抛错时回退到说明弹窗
- 验证安装完成事件到来后，相关状态能够更新且按钮不再显示

自动化测试需要允许 mock 或注入以下浏览器能力：

- `window.matchMedia`
- `window.navigator.standalone`
- `beforeinstallprompt` 事件对象
- `appinstalled` 事件
